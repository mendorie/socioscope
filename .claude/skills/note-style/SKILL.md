# note 記事を著者の文体に揃える: `/note-style <記事ファイル or report>`

著者が note（<https://note.com/mendorie>）で公開した 11 本（2026-10-06〜2026-11-12）と、公開前に著者自身が入れた手直しから抽出した規約。
迷ったら、同じ種類の直近の公開記事を 1 本読んで合わせる。公開版が常に正で、この文書より優先する。

## 手順

1. **種類を決める**: 本編（単発）／シリーズの partN／番外編。構成は下の「構成」に従う。
2. **材料を読む**: 元の report（`themes/<slug>/reports/`）と、同じシリーズの直前の `docs/articles/*.final.md`。
3. **書く・直す**: 「文体」「言い換え」「削るもの」「note の書式」を適用する。数値・出典・判定は report から変えない。
4. **機械チェック**: `python3 -I .claude/skills/yomiyasu/scripts/yomiyasu_lint.py <file>`（`make note-lint`）。警告は 1 件ずつ判断し、規約と衝突するものは残してよい。
5. **自己点検**: 末尾の「公開前チェック」を通す。
6. **報告**: 元の依頼にない追加・削除（節の追加、タイトル変更など）は必ず著者に伝える。公開・タグ設定は著者の指示があるときだけ行う。

## 構成

### 本編・シリーズの partN（7,500〜17,000 字、図 5〜10 枚）

```
## 前回までの振り返り        ← part2 以降のみ。本編単発にはない
## 1. 背景・分析論点の概要
### N つの仮説（候補）と、それぞれなら何が見えるはずか   ← 任意
## 2. サマリ（分析結果の要点）
## 3. 利用したデータ
## 4. 分析方法の概要
## 5. 分析結果
### 証拠 1: <結果を言い切る一文>      ← 政策論点の記事では「論点 1: <問い>」
## 6. 総括
### 結論
### <仮説・候補>はどうなったか
### 結論を覆しうる留意点
### 言えないこと
### ここまでの N 回で分かったこと     ← シリーズのみ。最終回は「N 回で分かったこと」
---
### 出典とライセンス
```

- **前回までの振り返り**: 「このシリーズでは、〜を N 回に分けて調べています。」→ 各回 1 項目の箇条書き `- [partN タイトル](URL): 要約 1〜2 文` → 「今回は、〜を確かめます。」。要約は、その回の公開版で著者が使った言い回しをそのまま使う。
- **1. 背景**: 前回残った問い、または世の中の議論から入る。問いを 1 つに絞り、仮説を箇条書きで並べる（`- **仮説1: 名前**。もし正しければ見えるはずのこと`）。
- **2. サマリ**: 冒頭に太字の段落で答えを言い切り、続けて箇条書きで補足する。主要な数値をここで出す。
- **証拠の見出し**: 「証拠 2: 交際相手のいない未婚者は、男女とも 35 ポイント前後増えた」のように、数値入りで結果を言い切る。
- **証拠の本文**: 図 → 図が示す数値 → 読み方 → 「ただし」で限界、の順。
- **結論**: 太字の一文で主張 → 根拠の数値 → 太字の「ただし〜」で限界。
- **留意点**: 番号付きリスト。`1. **要点を一文で。** 説明`。2〜3 個。
- **言えないこと**: 因果ではないこと、測れていないことを 1 段落で。

### 番外編（4,000〜4,500 字、図 2〜4 枚）

番号なしの平易な見出しにする。`## はじめに`（または `## 問い`）→ `## サマリ` → `## 何を調べたか`（`## 何を測ったか`）→ 結果ごとの見出し（「不信が強い国ほど『減らす』と言う」「結果: 見立てと逆だった」「深掘り 1: 〜」）→ `## どう読むか` → `## 出典とライセンス`。
冒頭で本編にリンクし、「そこで素朴な疑問が生じました」のように問いの出どころを書く。

### タイトル

- 問いの形か、結論の言い切り。「AなのかBなのか」「〜は本当か？」「〜でも〜でもない」。
- 比喩や省略でなく、原因・対象を具体的に書く（「意思か、出会いか」→「意思が下がったからか、出会いが減ったからか」、「非正規」→「非正規雇用」）。
- シリーズは note 上で ` | <シリーズ名> partN` を付ける。番外編は ` (番外編)` ` (番外編 2)`。記事ファイルの `#` 見出しにはシリーズ名を入れない。

## 文体

- **です・ます体**。結果の報告は過去形（「〜でした」「〜ませんでした」）、解釈や一般的な説明は現在形。「である」調は使わない。
- **一人称は「私」**。「筆者」は使わない。意見を述べる箇所だけに使い、「私個人の主観的意見としては」「私の見立ては〜でした」のように事実と区別して書く。「だと考えます」で締めるのも可。
- **一文は 50〜60 字**が目安。段落は 150〜200 字、長くても 300 字台。長い段落は文の切れ目で改行して分ける。
- **言い切る**。確かめたことは「〜でした」、確かめられなかったことは「〜は確かめられませんでした」「〜とは言えません」。「〜かもしれません」「〜と思われます」を重ねない。
- **数値を必ず添える**。「大きく増えた」ではなく「36.8% → 72.1%（+35.3 ポイント）」。変化は `A → B`、差は「ポイント」、割合は「約 4 分の 1（25%）」のように直感的な言い方と数値を併記する。
- **相関と因果を区別する**。「並走する」「関連する」「整合する」「説明できる」を使い、「原因だ」「〜のせいで」とは書かない。
- **逆接は「ただし」「しかし」「一方で」**、まとめは「つまり」。問いかけは 1 記事に 1〜3 回まで。
- 専門用語は初出で括弧書きの説明を付ける（「Kitagawa 分解」「到達の失敗（結婚する意思はあるのに、相手に出会えていない）」「偏り(セレクションバイアス)」）。
- 軽い本音の括弧書きを著者が入れることがある（「〜なので自明ですが・・・」）。下書きでは足さない。著者が入れたものは消さない。

## 言い換え（著者が実際に直した例）

| 下書きに出がちな表現 | 著者の表現 |
|---|---|
| N 回目 | partN |
| 筆者 | 私 |
| 国を並べて／国を並べたとき | 国の間で比較したときに |
| 〜の側で起きている | 〜の影響が大きい／〜が主因 |
| 結婚からの離脱 | 結婚しない人の増加 |
| 先送りしながら | 出産が高齢化しながらも |
| 家族形成を阻む | 婚姻・出産を阻む |
| 条件 | 外的条件 |
| 読み（仮説の意味で） | 仮説 |
| データを見る前に決めました | 事前定義しました |
| 〜にあたります | 〜を補填する構造でした（何をしているかを動詞で書く） |
| 本シリーズの限界 | 本シリーズにおける検証の限界 |
| 結論を覆しうる条件（3 つ） | 結論を覆しうる留意点 |
| 穴を埋めた／外れた／形が見えた | 補った／減った／どう〜したのかが分かった |
| 無く、無い | なく、ない |

共通する方向: **比喩・擬人化・体言止めの抽象語を、誰が何をどうしたかが分かる言葉に置き換える**。置き換え先が思いつかないときは、数値か主語を足す。

## 削るもの

- **事前登録の手続き**: 判定規則の細部、頑健性仕様の列挙、「細則をいつ決めたか」の説明。「事前の基準」と 1 句で触れるだけにする。詳細は report に残し、出典節からリンクする。
- 図と表で同じ内容を二重に見せること。用語説明の重複。
- 「この区別は総括で詳しく書きます」のような予告文。
- AI 調の定型: 「〜と言えるでしょう」「重要なのは〜です」「興味深いことに」「〜という物語」「鍵を握る」「浮き彫りになる」、絵文字、過剰な「」強調、三点並列の決まり文句。

## note の書式

- **表は使わない**（note は表を表示できない）。`- **項目名**。説明` の箇条書きにする。
- **太字**: 1 記事 20〜30 か所。サマリ冒頭の段落、結論の主張、各証拠で最も重要な 1 文、箇条書きの項目名に付ける。文の途中から太字にするときは句点の前で閉じる（`**〜でした**。`）。
- **図**: 記事ファイルでは `【画像を挿入: <file>.png】` の次の行に `*キャプション*`。キャプションは図の主要な数値を文で書き、最後に `出典: 〜を加工`（2 枚目以降は `出典: 同上`）。
- **箇条書き**: サマリの補足、データの一覧、仮説の一覧、結果の一覧に使う。本文の論理展開は地の文で書く。
- **数字と欧文の前後に半角スペース**を入れる（「2 人」「part6 で」「19 か国」）。範囲は「〜」、マイナスは「−」。
- **末尾**: 区切り線 → `### 出典とライセンス`。データごとに出典表記とライセンス、最後に「分析コードと詳細レポート（〜）は GitHub の socioscope リポジトリで公開しています（コードは MIT ライセンス）: <URL>」「図を転載する場合は上記の出典表記を付けてください。」。

## タグ（公開を頼まれたとき）

8〜10 個。`データ分析` は毎回付ける。テーマの検索語（少子化系: 少子化・出生率・少子化対策・少子化問題／政治系: 政治・国会・定数削減・議員定数）に、その回の主題語（結婚・未婚化・非正規雇用など）と分野語（社会学・統計・因果推論・社会問題）を足す。

## 公開前チェック

- [ ] 「筆者」「N 回目」「である。」「無く」が残っていない（`grep -nE '筆者|[0-9] 回目|である。|無[くい]'`）
- [ ] 表（`|---|`）が残っていない
- [ ] part2 以降は、冒頭に公開済みの全 part へのリンクがあり、URL が実在する
- [ ] サマリ冒頭と結論が太字の言い切りで始まり、数値が入っている
- [ ] 比喩・抽象語を具体的な言葉に置き換えた（言い換え表）
- [ ] 事前登録の細部を削った
- [ ] 数値・出典・判定が report と一致している
- [ ] 相関を因果として書いていない。「言えないこと」がある
- [ ] 300 字を大きく超える段落がない

## 公開後

著者は note 上で最終の手直しをしてから公開する。公開後は公開版と記事ファイルの差を確認し、ファイルを公開版に同期する。新しい種類の手直しが見つかったら、この文書の「言い換え」に 1 行足す。
