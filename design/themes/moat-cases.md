# テーマ: 「誰でもソフトウェアを作れる時代」に資本力で勝る競合へ MOAT を築けた企業・築けなかった企業

作成 2026-11-15。**事例を集める前**に問い・事例の選び方・MOAT の類型・判定基準を固定する。
本テーマは国×年のパネルではなく、企業事例の**比較事例分析（comparative case study）**である。
データの正は `research_notes/MOAT 成功失敗事例分析/*.md`（出典付きの事実）と、それを集約した `reports/` の report。

## 動機
クラウド・OSS・ノーコード・生成 AI（コーディング支援）により、ソフトウェア／アプリの「作ること」自体の
参入障壁は下がり続けている。機能はすぐ模倣され、巨大資本（Microsoft・Google・Adobe・Amazon・Meta・
リクルート等）は資金・配布網・既存顧客基盤で後発参入できる。この環境で、
(a) 資本で劣る新興企業が市場を取り、守り切った事例は**何を**堀（MOAT）にしたのか、
(b) 初期市場を取ったのに巨大資本に奪われた事例は**何をした／しなかった**のか、
を双方の事例から同じ枠組みで比較し、「機能ではなく何が堀になるか」の示唆を得る。

## 問い
1. **Q1 成功側**: 資本で劣りながら、同カテゴリで巨大資本の参入・模倣・バンドルを受けつつシェアを維持・拡大した企業は、どの MOAT 類型を、いつ（参入前／参入後）、どの順序で築いたか。
2. **Q2 失敗側**: 初期にカテゴリ首位・急成長したのち、巨大資本に市場を奪われた企業は、(i) どの MOAT を持っていると当時主張し、(ii) 実際には何が欠けていたか。失敗の直接原因（バンドル・プラットフォーム依存・機能模倣・単機能・収益化遅れ等）を分類する。
3. **Q3 時代差**: 2015 年以降（特に 2022 年以降の生成 AI 期）に有効性が**上がった**MOAT と**下がった**MOAT はあるか。「作りやすさ」が堀の性質を変えたと言えるか。
4. **Q4 業界差**: 人材業界（求人メディア・HR SaaS・スキマバイト・採用管理）とテック業界一般で、有効な MOAT の類型は異なるか。両面市場（求職者×企業）特有の堀はあるか。

## 事例の選び方（事前登録）
恣意的な「勝者の後知恵」を避けるため、次を**事例を集める前**に固定する。
- **対象期間**: 2005 年以降に創業、または 2005 年以降に当該カテゴリへ参入した企業。古典事例（Netscape・Lotus 等）は「参照」として別枠で扱い、本分析の母集団に入れない。
- **資本差の条件**: 当該市場に参入・対抗した競合が、その時点で**時価総額または年間売上で 10 倍以上**の企業（またはその子会社）であること。資本差がない同世代スタートアップ同士の競争は対象外。
- **成功の定義**: 巨大資本の参入・模倣・バンドル後も **5 年以上**、当該カテゴリで (a) シェア首位または上位 2 位を維持し、(b) 売上または利用者が拡大し続け、(c) 独立企業として存続、または主要カテゴリで首位のまま高倍率で買収された（買収後も製品・ブランドが存続）こと。
- **失敗の定義**: 一時期カテゴリ首位または最速成長を記録したのち、巨大資本の参入後 **5 年以内**に (a) シェアを大きく失い、(b) 事業縮小・撤退・廃業・ピーク評価額を大幅に下回る売却のいずれかに至ったこと。
- **混合（中間）**: 存続したがシェアを明確に失った（例: Slack・Dropbox 型）は「混合」として別カテゴリで記録し、成功・失敗のどちらにも数えない。
- **選定の記録**: 候補に挙げたが上の条件を満たさず落とした事例は、理由とともに note に残す（選択バイアスの可視化）。
- **業界の割付**: テック（SaaS・コンシューマ・開発者ツール・AI）と人材（求人メディア・HR SaaS・スキマバイト・採用管理）を分け、各区分で成功・失敗の両方を最低 3 例ずつ集める。日本の事例を各区分に最低 2 例含める。

## MOAT の類型（コード表、事前固定）
Helmer『7 Powers』を骨格に、ソフトウェア特有の要素を加える。各事例に主・副を付与する。
| コード | 類型 | 定義（この分析での操作的定義） |
|---|---|---|
| NE-D | 直接ネットワーク効果 | 同じ側の利用者が増えるほど価値が増す（コミュニケーション・コミュニティ） |
| NE-X | 間接・両面ネットワーク効果 | 片側（求職者・開発者・出店者）の増加が他側の価値を増す |
| NE-DATA | データ・学習効果 | 利用で蓄積されるデータが製品品質を改善し、後発が同等品質を出せない |
| SC-DATA | スイッチングコスト（データ・記録） | 業務記録（system of record）が蓄積され、移行コストが高い |
| SC-WF | スイッチングコスト（ワークフロー・統合） | 他ツール・社内プロセス・API 連携に埋め込まれ、置き換えが組織的に困難 |
| SCALE | 規模の経済 | 固定費（インフラ・営業・コンプライアンス）を大きな売上で薄められる |
| BRAND | ブランド | 同等機能でも選ばれる・価格を上げられる信頼・象徴 |
| CP | カウンターポジショニング | 既存大手が自社事業を傷めるため追随できないビジネスモデル（価格・無料・流通） |
| CR | コーナード・リソース | 独占的に押さえた資源（規制ライセンス・独自データ源・人材・IP） |
| PP | プロセスパワー | 長期に蓄積された組織能力・運用ノウハウで模倣に時間がかかる |
| DIST | 流通・配布網 | 既存顧客基盤・OS／ブラウザ同梱・営業網など、製品に先立つ到達手段 |
| ECO | エコシステム | 第三者開発者・テンプレート・コミュニティが製品価値を補完する |
| SPEED | 速度・実行力（非 MOAT） | 継続的に先行して出し続ける力。7 Powers では堀とみなされないため、別記して「堀と呼べるか」を検討する |

## 失敗の直接原因の類型（コード表、事前固定）
| コード | 類型 |
|---|---|
| F-BUNDLE | 巨大資本の既存製品へのバンドル（無料同梱）で選ばれなくなった |
| F-PLATFORM | 依存していたプラットフォーム（OS・SNS・API・検索）の方針変更で供給／流通を断たれた |
| F-COPY | 中核機能を模倣され、差分が消えた（スイッチングコストが無かった） |
| F-SINGLE | 単機能で、隣接機能を持つ製品のサブ機能に吸収された |
| F-ECON | 単位経済（CAC・粗利）が成り立たず、資本戦で持久できなかった |
| F-SUPPLY | 両面市場の供給側（求人・コンテンツ・出店者）を競合に奪われた |
| F-TECH | 技術シフト（モバイル・クラウド・生成 AI）への移行が遅れた |
| F-SELF | 自滅（経営・品質・不祥事）で、巨大資本の参入は主因でない → 対象外または参照扱い |

## 仮説（事前登録、2026-11-15）
事例を見る前の予想。判定基準は事例集計後も変えない（変える場合は日付と理由を書き足す）。
- **H1（機能は堀にならない）**: 成功事例の主 MOAT に `SPEED` 単独や「機能の優位」が挙げられる事例は 2 割未満。成功事例の 8 割以上は NE-*・SC-*・CP・DIST・ECO のいずれかを主 MOAT として持つ。判定: 比率で判定。
- **H2（失敗の最多原因はバンドルと単機能）**: 失敗事例の直接原因で `F-BUNDLE` と `F-SINGLE` の合計が過半を占める。判定: 比率 ≥ 50% で整合、< 30% で不支持。
- **H3（カウンターポジショニングは参入前に築かれる）**: 成功事例のうち CP を持つものは、巨大資本の参入**前**に価格・流通モデルを確立している（参入後に CP を作った例はない）。判定: 参入後に CP を築いた成功例が 1 つでもあれば不支持。
- **H4（人材業界は供給側ネットワーク効果が決定的）**: 人材業界の成功・失敗を分けるのは NE-X（求人・求職者両面の供給獲得）であり、UI・機能・ブランドではない。判定: 人材の成功例の主 MOAT に NE-X または CR（独自の求人／求職者データ）が 7 割以上、失敗例の直接原因に F-SUPPLY が 5 割以上。
- **H5（生成 AI 期は配布と記録が強まり、モデル優位は弱まる）**: 2022 年以降の事例では、モデル・アルゴリズム自体の優位を主 MOAT とした企業は 3 年以内にシェアを失い、DIST・SC-DATA・SC-WF を持つ企業が残る。判定: AI 期事例でモデル優位のみを堀とした成功例があれば不支持。
- **H6（巨大資本側の制約が堀を生む）**: 成功事例の半数以上で、巨大資本側に「追随できない構造的理由」（既存売上の共食い・規制・組織の優先度・反トラスト審査）が確認できる。

## 指標・出典の優先順位
数値は一次資料（S-1・10-K・有価証券報告書・決算説明・公式発表）＞ 業界調査（Gartner・IDC・Sensor Tower・Similarweb）＞ 信頼できる報道（WSJ・FT・日経・The Information・TechCrunch）＞ 二次まとめ（Wikipedia・ブログ）。
各事例で最低限そろえる値: 創業年、巨大資本の参入・模倣・バンドルの年、その時点の資本差（売上・時価総額）、参入前後の売上・利用者・シェア推移、結末（独立存続・買収額・撤退年）、企業自身が主張した堀（S-1 の Competitive Strengths・経営者発言）。

## 限界（事前に認識）
- 事例分析は因果を証明しない。「成功企業が持っていた MOAT」は生存者バイアスを受ける。対照として「同じ MOAT を持ちながら失敗した例」を必ず探す。
- 「成功」判定は 2026-11 時点のスナップショット。Cursor・タイミー等の進行中事例は「暫定」と明記する。
- MOAT の付与は分析者の判断を含む。付与の根拠（出典）を各事例に残し、別の読み方が可能な場合は併記する。

## 結果（事後記録、2026-11-16。判定基準は不変）
report: `reports/MOAT 誰でも作れる時代に資本に勝った企業と負けた企業.md`、集計: `research_notes/MOAT 成功失敗事例分析/cross_case_coding.md`。
- H1 整合（SPEED 主 0/16、NE/SC/CP/DIST/ECO 主 15/16）。
- H2 不支持（F-BUNDLE＋F-SINGLE 主 2/13）。事後再分類: 「配布網に載せた模倣」（BUNDLE＋COPY＋PLATFORM）9/13。
- H3: 字義どおり（参入前に確立）に読むと Datadog・Snowflake が反例で**不支持**。「攻撃への反応として参入後に CP を築いた成功例はない」の読みでは整合。後者の読みは 2026-11-16 に事例を見た後で追加した読み替え（理由: 両社は巨大資本の製品が先行する市場に創業時から CP を持って参入しており、事前登録時に想定していなかった型）。判定基準そのものは変えていない。
- H4 不支持（成功の NE-X/CR 主 2/4、失敗の F-SUPPLY 主 0/2）。事後分割（探索的、NE-D を含む）: 求人メディア 4/4 がネットワーク効果、HR SaaS 0/5。
- H5 暫定整合（モデル優位のみで 3 年持った成功例 0）。
- H6 整合（12/16、成功確立後の制約を除くと 10/16）。反例: リクルートの自発的共食い。
